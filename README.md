# BYOW 数据结构大作业

基于 CS61B Project 3「Build Your Own World」的项目思路。核心数据结构、游戏逻辑和图形均提供 C++17 实现；原 Java TileEngine 版本继续保留作为兼容回退。程序完全离线运行，不调用网络算法接口。

当前原生版的完整玩法、八关参数、界面、角色、配乐与开发状态见[《花神遗迹》玩家手册与开发交接](游戏交接说明.md)。

## 运行

**C++ 原生原型（Windows 优先）**。Windows 用户可在 `platforms/Windows/Native/` 双击 `byow_native.exe`，无需安装 JDK、Python 或 IDE。首页按 `C` 可挑选八位探险者；选中角色后会显示全身动画和简介，点击右上角的 × 或按 Esc 返回首页，保留已选角色。源码构建需要 CMake 3.24+、Git 和 C++17 编译器，首次配置会获取固定版本 SFML 3.0.2。

首页可直接开始第一关、进入选关地图或使用自定义种子。每关出发前会显示时间、步数和地形消耗上限。八关时限从 8 分钟逐步降到 4 分钟，拾取时钟可增加 30 秒。集齐四朵花后抵达出口即可通关。每个预设关卡首次通关会复苏一朵遗迹之花，八关共八朵。

按住方向键或 WASD 可连续走动。地面、沙地和木桥分别消耗 1、5、3。用 Shift 加方向跨过一格碎石，消耗 3 并记作一步。池水只能走桥通过。点击地图选目标，按 `1/2/3` 切换 BFS、Dijkstra、A*，按 `E` 沿路线行走或停止。守卫预警时应离开红圈，空格攻击相邻守卫，药剂恢复 45 点生命。完整规则可在首页按 F1 查看，按 C 可切换角色。

**Java 兼容版**：

**macOS（Apple Silicon）**：双击 `platforms/macOS/BYOW.app`。应用内含精简 Java 运行时，无须另装 Java/Python。需在 Mac 上运行 `python3 package_macos.py` 生成应用包。

进入后按 `N`，输入种子（例如 `2026`），按 `S` 开始。主菜单 `L` 读取存档 1，`Q` 退出。界面直接使用官方 `TERenderer.java`、`TETile.java` 和 `Tileset.java`，保留黑底、Monaco 字体、粉灰色 `#` 墙壁、绿色地板及白色 `@`。

**从源码运行（macOS / Windows / Linux）**：需要 Python 3.10+、C++17 编译器（clang++ 或 g++）、JDK 17+。

```sh
python3 run.py
```

macOS 也可双击 `platforms/macOS/启动游戏.command`。Windows 的 `platforms/Windows/启动游戏.bat` 优先打开已安装的原生版，没有原生版时会回退到 Java 兼容版；可用 `启动游戏.bat --java` 主动选择兼容版。从源码启动首次运行会编译。Windows 免安装发行包（`BYOW.exe`、应用文件和 runtime）以及 macOS `.app` 都是平台专属构建产物，不纳入 Git；推送仓库时包含共用源码、平台启动脚本和打包说明，用户可在对应平台重新构建应用包。

## Java 兼容版玩法

收集地图中的 **4 朵花**（官方 `FLOWER` 砖块），然后到达橙色出口。粉色 `#` 是墙，绿色点是地板，黄色 `SAND` 为高代价地形，红色 `g` 是守卫，红色 `+` 是一次性生命恢复点。

- 初始生命 100，恢复点在非满血时回复 30 点，不会超出 100。
- 守卫每 3 个有效回合行动一次，近处以 BFS 追踪，远处在两个目标间巡逻。相邻时造成 8 点伤害；玩家两次相邻攻击可击败一个守卫。
- 普通地面进入代价为 1，沙地为 5。代价用于寻路比较和累计统计；进入沙地仍是一回合，不扣生命。
- 撞墙、试图进入守卫所在格不会消耗回合。攻击、等待会消耗回合。
- 默认显示全图，便于课程演示；开启视线后，墙会遮挡视野，未探索区域隐藏，探索过的区域保留暗色记忆。

| 按键 | 功能 |
|---|---|
| WASD / 方向键 | 移动 |
| 空格 / F | 攻击上下左右相邻守卫 |
| . | 等待一回合 |
| 鼠标点击地面 | 选取寻路目标 |
| 1 / 2 / 3 | BFS / Dijkstra / A* |
| E | 沿规划路径自动前进 / 停止；接近守卫或受伤会停止 |
| H | 显示或隐藏玩家路线 |
| G | 显示或隐藏守卫下一阶段的规划路线 |
| V / T | 搜索展开节点 / 按实际展开顺序播放 |
| B | 同一目标的三种算法对照 |
| L | 开关视线遮挡；开启时只允许选择当前可见目标 |
| M | 显示房间图；绿色为最小生成树边，黄色为额外边 |
| U / Z | 撤销一次输入，完整恢复地图探索、敌人、物品和生命 |
| P | 存档菜单：1/2/3 选槽，S 保存，L 读取，R 重放 |
| N | 新游戏，不需退出程序 |
| :Q | 依次输入冒号、Q，保存到存档 1 并退出 |
| ESC | 返回菜单 / 返回上一页；主菜单 R 可继续当前世界 |
| ? | 帮助 |

存档位于程序文件夹的 `saves/slot1.txt` 至 `slot3.txt`，由种子和行动序列组成。存档重放结束后可继续游戏。单次旅程最多记录 20,000 次输入。显示开关、鼠标目标和所选算法不属于游戏状态，读取时目标清空。

## 数据结构实际应用

| 内容 | 用途 | 源码 |
|---|---|---|
| 并查集（路径压缩、按大小合并） | Kruskal 判环，确保所有房间连通 | `src/structures.hpp` |
| 最小生成树 Kruskal | 12 个房间的完全图按曼哈顿距离选 11 条连接边，再加 3 条边形成环路 | `src/engine.hpp`，`World::generate` |
| 邻接表 | 可行走格作为顶点、四邻格作为边，目标格决定进入代价 | `World::adjacency` |
| 自实现循环队列 | BFS 最少步数寻路、守卫追踪及连通距离 | `RingQueue`、`World::search` |
| 自实现二叉最小堆 | Dijkstra 松弛及 A* 启发式搜索的候选结点管理 | `MinHeap`、`World::search` |
| 顺序表、前驱数组 | 保存路径并反向重建，保存实际搜索展开顺序 | `SearchResult` |
| 行动序列栈式撤销 | 移除末次输入后确定性重建完整状态 | `java/core/Main.java` 与 `Game::replay` |
| 视线光栅遍历 | Bresenham 光线与墙壁遮挡 | `Game::lineOfSight` |

Kruskal 的最优性针对**房间中心抽象图**，不表示最终格子通道总长度全局最短。额外边和穿越已有房间的通道会改变最终格子图结构。BFS 只保证步数最少，Dijkstra 和 A* 保证带权通行代价最小；A* 使用曼哈顿距离，因最小边权为 1，启发式可采纳且一致。寻路图不把移动守卫作为静态障碍；实际移动和自动行走会另行检查守卫。

## 验证

```sh
python3 tests/verify.py
```

测试对照独立的 Prim、标准库优先队列最短路与队列参考结果，而不是仅检查界面能否打开。覆盖 200 个世界种子、2,400 个起终点组合（三种算法共 7,200 条路径），以及地图连通性、边界、带权绕路、不可达目标、战斗、治疗、通关、视线遮挡、确定性重放、Java/C++ 进程通信、三个存档槽、损坏存档拒绝。

测试结果见 `tests/验证记录.txt`；界面截图见 `screenshots/`。目前未生成实验报告和讲解视频。

## 目录

```text
src/                   C++ 数据结构、图算法、游戏状态和原生界面
java/core/             原版窗口的输入/显示适配、JSON 读取、存档
java/vendor/           官方 TileEngine、RandomUtils 和 StdDraw 原始源码
platforms/macOS/       macOS 启动入口与打包说明；BYOW.app 为本机生成
platforms/Windows/     Windows 启动入口与打包说明；发行包为本机生成
build/byow.jar         Java 桌面入口；C++ 算法不在 jar 中
build/relic_engine     当前平台的 C++ 核心
tests/                 可复现测试与验证记录
screenshots/           实际桌面截图
saves/                 本机存档
run.py                 源码编译与运行入口
package_macos.py       使用官方 jlink/jpackage 生成 platforms/macOS/BYOW.app
THIRD_PARTY.md         框架来源与复用范围
```

`package_macos.py` 可重新生成当前平台的 `.app`。需先退出游戏，避免覆盖运行中的应用。
